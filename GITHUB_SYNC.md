# Версия дневника с синхронизацией через GitHub

Открыть: https://oestepanov.github.io/my-training/github.html

Интерфейс загружается с GitHub Pages. Единственная удалённая служба этой версии — GitHub API. История хранится в ветке `training-data`, файл `diary.enc.json`. Обновление истории не запускает публикацию интерфейса из `main`.

## Подключение первого устройства

1. В GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens создайте ключ для владельца `Oestepanov`.
2. В Repository access выберите **Only select repositories**, затем **my-training**.
3. В Repository permissions выберите **Contents: Read and write**. Остальные разрешения не требуются; Metadata выдаётся GitHub автоматически.
4. Откройте дневник, нажмите **Подключить GitHub**, раскройте **Первое подключение**.
5. Вставьте ключ GitHub и код восстановления, переданный отдельно при переносе истории. Нажмите **Подключить дневник**.

Ключ GitHub не нужно присылать в чат. Он хранится только в памяти браузера этого устройства и передаётся только `api.github.com` для запросов к репозиторию. Срок действия выбирается при создании ключа.

## Остальные устройства

На первом устройстве откройте **Синхронизация → Код для другого устройства**. На другом устройстве откройте тот же адрес `github.html` и вставьте код в поле подключения. В коде находятся доступ к GitHub и ключ расшифровки; передавайте его только своим устройствам.

## Сохранение и конфликты

Результат сначала записывается в память браузера, затем отправляется на GitHub. Статус показывает, остались ли неотправленные изменения. При восстановлении связи и открытом дневнике отправка повторяется автоматически. Чтение обновлений выполняется каждые 30 секунд, когда форма не изменяется; есть кнопка ручной синхронизации.

Разные занятия с разных устройств объединяются. Если одну запись одновременно меняли на двух устройствах, очередь сохраняется до явного выбора версии в настройках синхронизации. Обновления GitHub используют SHA файла и проверку версии занятия. Удаление и восстановление передаются как изменения статуса корзины.

## Защита данных

Записи шифруются AES-256-GCM до отправки на GitHub. Ключ расшифровки отсутствует в исходниках и в ветке с историей. Смена ключа GitHub не требует смены ключа расшифровки: для нового подключения используйте прежний код восстановления.

Данные и доступ в браузере удаляются при очистке данных сайта. До очистки убедитесь, что очередь пуста и код подключения сохранён. Кнопка **Скачать записи** сохраняет незашифрованную резервную копию занятий на ваше устройство.

## Проверки

`node --test github-store.test.cjs`: шифрование, два устройства, очередь без сети, одновременные записи и редактирование, корзина, повтор после потери ответа, просроченный ключ, перенос подключения, заполненная память браузера.

Первое подключение пользователя и запись с его персональным ключом проверяются после настройки ключа на устройстве. Ключи и код восстановления не входят в этот репозиторий.
